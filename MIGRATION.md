# Dependency migration guide — React 18 → 19, RTK 1 → 2, ESLint 8 → 10

## Files changed

| File | What changed |
|------|-------------|
| `package.json` | All deps bumped, `eslint-config-airbnb` removed, flat config deps added, `prepare` script added for husky 9 |
| `eslint.config.js` | New file — replaces `.eslintrc.json` (ESLint flat config) |
| `.eslintrc.json` | **Delete this file** |
| `.husky/pre-commit` | Removed `source _/husky.sh` line (husky 9 format) |
| `.husky/_/` | **Delete this directory** — generated by husky 8, not needed in v9 |
| `src/index.tsx` | `import React` removed, `React.StrictMode` → named import `StrictMode` |
| `tsconfig.json` | `target` ES2020 → ES2022, `eslint.config.js` added to `include` |

---

## React 18 → 19

**No breaking changes in this codebase.** React 19 removed support for:
- `propTypes` — not used
- `defaultProps` on function components — not used
- `forwardRef` (deprecated, `ref` is now a regular prop) — not used
- Legacy string refs — not used

The only required change: `import React from 'react'` in `index.tsx` replaced with
named import `import { StrictMode } from 'react'`. React 19 still supports the
default import, but named imports are cleaner and tree-shake better.

---

## @reduxjs/toolkit 1.9 → 2.12

**No breaking changes in this codebase.** RTK 2.x removed:
- `getDefaultMiddleware()` — not used (project uses `configureStore` default middleware)
- Some internal type exports — not used directly

RTK 2.x improvements you now get for free:
- Better TypeScript inference on `createAsyncThunk`
- `combineSlices` API (not used here, but available)
- Smaller bundle size

---

## react-redux 8 → 9

**No breaking changes in this codebase.** react-redux 9 requires React 18+
(you now have React 19). The hook API (`useSelector`, `useDispatch`) is identical.

---

## react-router-dom 6 → 7

**No breaking changes in this codebase.** React Router 7 keeps full backward
compatibility with the v6 hooks API: `useNavigate`, `useParams`, `useLocation`,
`Navigate`, `Routes`, `Route`, `BrowserRouter`, `Link` — all work identically.

React Router 7 adds optional features (data APIs, framework mode) that this project
doesn't use. You get them for free if needed later.

---

## ESLint 8 → 10 + flat config

This is the most impactful change. ESLint 9+ uses **flat config** (`eslint.config.js`)
by default and deprecated the legacy `.eslintrc.*` format.

**Why `eslint-config-airbnb` was removed:**
`eslint-config-airbnb` requires ESLint `^7.32.0 || ^8.2.0` — it is not compatible
with ESLint 9 or 10. The project now uses:

- `@eslint/js` — ESLint's own recommended rules (replaces `eslint:recommended`)
- `typescript-eslint` — replaces `@typescript-eslint/*` with unified package
- `eslint-plugin-react` — same plugin, flat config format
- `eslint-plugin-react-hooks` — upgraded to v7 (supports React 19)
- `@vitest/eslint-plugin` — replaces `eslint-plugin-vitest` (official Vitest plugin)

The rule coverage is equivalent. Airbnb rules that matter for TypeScript projects
are covered by `typescript-eslint/recommended`.

---

## Husky 8 → 9

Husky 9 changed the hook format. Hooks no longer need to source `_/husky.sh`:

```sh
# husky 8 format (old) — REMOVE THIS LINE
. "$(dirname -- "$0")/_/husky.sh"

# husky 9 format — just your commands, nothing else
echo "Running pre-commit checks..."
```

The `prepare` script in `package.json` also changed:
```json
// husky 8
"prepare": "husky install"

// husky 9
"prepare": "husky"
```

After running `npm install`, husky 9 auto-initializes from the `prepare` script.
Delete the `.husky/_/` directory — it is no longer generated or needed.

## How to apply

```bash
# 1. Create and switch to the branch
git checkout -b feat/update-dependencies

# 2. Copy updated files (or apply changes manually per table above)

# 3. Delete old ESLint config and husky internals
rm .eslintrc.json
rm -rf .husky/_/

# 4. Install updated dependencies
npm install

# 5. Verify everything works
npm run typecheck
npm run lint
npm run test:ci
npm run build
```
